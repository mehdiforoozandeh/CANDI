WHY THIS IS THE WHOLE FIX. The column order is the index into the FILTERED aliases.json
experiment_aliases key order (data.py:187-191), with the control at control_assay_id = num_assays
(data.py:195). That order is established by _make_alias (data.py:283-316) as
data_matrix.count().sort_values(ascending=False) — which is (a) data-dependent, (b) UNSTABLE on ties
(pandas defaults to quicksort), and (c) seeded by os.listdir order. Two bakes of the same directory on
different filesystems can legitimately produce different orders. So the order can only be DERIVED and
RECORDED, never declared. Four assertions at bake:
  1. set(panel.assays) <= set(handler.includes)                       -> catches F1 (silent column loss)
  2. assert_panel_bijection(panel.assays, resolve_column_order(h))    -> catches the permutation
  3. [h.assay_to_id[a] for a in resolved] == list(range(len(resolved)))
  4. h.control_assay_id == len(resolved)
and one at load: assert json.loads(h5.attrs['assays']) matches the checkpoint's recorded order.

## RISKS
- CONSTRUCTOR RNG DRIFT breaks --compat-q19 permanently and silently. model.py collapses two class layers (RealDualCondDecoder into DualCondDecoder, and RealMetaEmbedder into an alias) and swaps DualCondMetaEmbedder for an 8-line stub. Each is individually audited as RNG-neutral, but the composition is not proven until Gate A runs. Highest-probability failure and the reason Gate A is first. Mitigations: the stub's embedding table must stay 8xE and NOT scale with num_assays; film_proj must be constructed-then-zeroed, not created as zeros; hidden_projs must remain an empty ModuleList when fusion_deep=False; output_norm must stay nn.Identity; transformer_film_layers must stay None; both discarded placeholders must still be constructed in place. If Gate A fails, fall back to keeping the exact two-class inheritance from model_real.py verbatim and re-run.
- x-transformers version drift. 2.11.23 is a PyPI (not CVMFS) install, it is fast-moving, and its internals fix both the encoder.transformer_blocks.* state_dict key names and the per-module init order. A minor bump breaks checkpoint loading AND the RNG stream. The == pin is necessary but not sufficient — a co-worker on a fresh machine can still resolve a different build. Gate A must assert importlib.metadata.version('x-transformers') == '2.11.23' explicitly, since the package has no __version__ attribute.
- The 2347-line COPY+EDIT of repo-root data.py is the largest single vendored artifact and the one edit set that cannot be verified by unit test alone (its correctness surfaces only through the bake). Edit E1 in particular must land BEFORE _load_blacklist runs at line 129, inside __init__, or the handler dies on construction. Edits E3 (DSF fallback) and E5 (run_type else-raise) change behaviour on data that has never been exercised — they are correct but they will make previously-silent malformed inputs fail loudly, which will read as a regression to anyone who does not read DATA.md. Gate C's C6 negative-control cases exist for exactly this.
- meta_dsf zero-vs-minus-one (bake edit B6) is the highest-impact latent bug and its fix changes the schema semantics. Any h5 baked before the fix that had an absent DSF level is silently poisoned — every assay marked available at log2(depth)=0 with all-zero counts, loss descending, metrics garbage. The kit must refuse to load a version=1 h5. Risk: the existing sandbox.h5 IS version 1, so Gate B either re-bakes (15 min, but exercises the derived assay order — preferred) or needs an in-place attr migration that must itself be validated.
- Derived assay order is not stable across filesystems. _make_alias sorts by data_matrix.count() with pandas' default UNSTABLE quicksort, over a column set seeded by os.listdir. Two bakes of the same directory can legitimately produce different orders on ties. The kit's answer is to derive-and-record rather than declare, but that means a checkpoint is only valid against an h5 whose recorded order matches. The load-time assert must compare against the ORDER STORED IN THE CHECKPOINT, not merely against the panel — and aliases.json must never be deleted once a bake exists.
- Gate B acceptance thresholds sit at the noise floor by design (+-0.09 macro crps_oracle_scaled, +-0.06 Spearman), which means the gate cannot distinguish 'the kit reproduces the recipe' from 'the kit has a small systematic regression'. This is a real limit of a 12-target / 4-cell-type panel, not a threshold-tuning problem. Gate B2's structural sign pattern (offset ON -> eta_slope ~ 0; offset OFF -> eta_slope >= 0.7) is the sharper test and should be treated as the primary criterion; B1 is a sanity band.
- Metric-file surgery risk: eval.py takes ~11 distinct edits (assay-order threading, three deletions, the <= -> < change, the foreground purity flag and tie-break, the M3 between-pool fix, the rename, the --include-deprecated gating). Changing the foreground tie-break in particular changes which positions are scored, so every recorded per-assay anchor shifts by an unknown amount and the Gate B anchors above become approximate. Mitigation: land the tie-break fix as an OPT-IN flag for the first validation pass so Gate B compares like with like, then flip the default once the delta is measured.
- GPU peak memory was never directly measured — the MIG pool sat inside the CDUMaintenance2 reservation during the audit. What is established is that 10/10 recorded arms completed on the 9.75 GiB slice at 3.10 M params / d_model 72 / context 768. A co-worker scaling to 35 assays (d_model 288) or context 1536 has no measured envelope, and the DNA tower grows as context_length * 25 bp of one-hot. Re-run /scratch/mforooz/tmp/candi_kit_probe/gpumem.sh after maintenance and put the number in DATA.md before shipping.
- Baking a large panel is expensive in a nearly-full filesystem: ~0.16 GB on disk and ~1.5 min per biosample at 8 assays / 7,485 windows, dominated by DNA (574.8 MB uncompressed per biosample, independent of assay count) and peaks stored as int64 for a 0/1 mask (367.9 MB, 8x waste). /project (def-maxwl) is at 23/28 TiB. The kit keeps pval+peaks verbatim so the extension hook stays usable, which costs ~460 MB uncompressed per biosample the counts-only recipe never reads. --out has no default and DATA.md must point at /scratch.
- test_masking.py and fixture.py are NOT ported, so the kit ships no test covering the masking invariants (control never masked, obs/imp == unmasked/masked, the mixed-meta swap) against real batched data. They depend on bake_fixture(), which needs the real EIC directory. Gate C partially covers this end to end, but there is no fast regression test for masking. Accepted gap; note it in README so the co-worker knows to run Gate C after any masking change.
- .gitignore's unanchored `jobs/` rule (line 15) silently swallows candi_kit/jobs/*.sh. The manifest names the directory `slurm/` to avoid it, and `models/` and `logs/` must be avoided for the same reason.
