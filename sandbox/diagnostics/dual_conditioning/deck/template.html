CANDI · dual metadata conditioning

Was the steering failure real?

A controlled test of whether the model can follow two instructions at once — and the one bug that faked a failure.
Mehdi Foroozandeh · Simon Fraser University · July 2026
The worry

Does the model actually use its metadata?

  • CANDI is supposed to read its metadata — sequencing depth, assay type — and adjust its output accordingly.
  • The failure we keep running into: the model quietly ignores that metadata. We call it collapse.
  • Today: a clean, controlled test of whether the model can use metadata to steer its output at all.
The setup

Two jobs, on purpose — in a testbed where we know the right answer

Job 1 · read the input corrupt the input (fx on) and ask for it back untouched (fy = none) → recover the clean signal
Job 2 · steer the output leave the input clean (fx = none) and demand a transformed output (fy on) → produce the reshaped answer on command

The symptom · part 2

Job 2 fails — the output ignores the instruction

The steering score S

S = how much the right instruction lowers error (0 = nothing, 1 = nails it) · P = number of instruction levels · Cij = error when the true answer is i but we told it j.
CRPS = how far the predicted distribution sits from the true count (a distributional error, in count units). Unlike NLL, it stays finite and robust when the model is surprised.
S ≈ 0.02  →  a dead knob.

Same model: it understands the input, but the output knob does nothing. This looked exactly like collapse.

Suspect 1 · the culprit

Pooling — the instructions were blurred together

The broken version mixed all the assays’ instructions into a single average before the decoder used it. Any one assay’s instruction got smeared out and lost.

Keep each assay’s instruction separate — and the knob comes alive.

0.02 → 0.53
steering score · a ~24× jump. Never dead — just blurred.
The culprit, up close

What “pooling” actually does — to the wiring

Pooling (v1): the decoder averaged every assay’s instruction into one blur, then fed that same blur to every assay — so assay 1’s own instruction was gone.

The fix: route each assay’s instruction straight to its own output. Nothing is averaged — every assay is steered by its own metadata.

This is the metadata-conditioning (FiLM) step: each assay’s metadata sets how its own features are scaled and shifted.
The payoff

So: the model can steer

The failure wasn’t a wall — it was one fixable wiring mistake.

Keep each assay’s instruction separate, and the model follows two independent commands at once: clean the input and reshape the output on demand — by genuinely reading the instruction, not cheating.

Caveat: this is a small, chr19-trained testbed. Whether it holds up when we combine transforms it never saw is exactly what we test next.
A twist

Undoing is harder than redoing

Asking the model to add a distortion to its output is basically free. The real work is cleaning up a distortion on the way in.

And the surprise: the distortion that trips it up isn’t the information-destroying ones (blurring, capping) — the model handles those fine. It’s a plain shift in the background level.

The real test

Combinations it never saw

We hid some input→output pairings from training entirely — then asked for them anyway.

The model still gets them right: it reads the instruction and composes, rather than memorising pairs. Hiding almost half of the combinations barely changes anything.

Takeaways

What we learned

  1. The model can do dual conditioning — read the input and steer the output at the same time.
  2. The earlier failure was one bug: pooling instructions across assays. Fixed → the knob works (~24×).
  3. It genuinely reads the instruction — and composes: combinations it never trained on still work, almost for free.
  4. The hard part is undoing the input, not producing the output — and the trouble spot is a shift in background level, not information loss.
